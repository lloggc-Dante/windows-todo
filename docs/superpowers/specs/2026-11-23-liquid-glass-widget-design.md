# 原生液态玻璃贴片与拖动修复设计

## 目标

修复当前只有小拖动柄可移动的问题，并把“只有透明”的贴片升级为具有真实背景柔化、折射高光、边缘流光和按钮光效的液态玻璃。

## 已确认方向

采用真实背景柔化与动态液态高光，而不是继续叠加静态透明渐变。保留 WPF 原生进程、JSON 协议、任务数据、八行滚动和全部交互。

## 技术方案

- 使用 WPF `WindowChrome` 与 DWM 原生背景合成实现真实背景柔化，避免 Electron 透明合成问题。
- 评估 `AllowsTransparency=False` + `WindowChrome.GlassFrameThickness=-1`，由 Windows 处理背景采样，WPF 处理圆角、卡片、文本和动态高光。
- 不使用之前失焦发白的 Acrylic 配置，不恢复 Electron BrowserWindow，不使用静态壁纸截图冒充实时玻璃。
- 如果 WindowChrome 与当前分层设置冲突，先调整窗口合成方式并验证实际效果，不通过降低材质目标掩盖问题。

## 拖动

- 在整个外壳监听非控件鼠标按下，标题空白、任务文字和普通背景都能移动窗口。
- 按钮、输入框、清单弹层和排序拖动柄保持各自操作，不触发窗口移动。
- 使用 WPF 原生 `DragMove()`，移动后仍向 Electron 报告最终位置。
- 保留右缘缩放和跨屏匹配逻辑。

## 液态材质

- 真实柔化背景上叠加低白度冷色渐变，避免只剩透明。
- 外壳具有折射亮边、顶部聚光、侧面流光和柔和外阴影。
- 卡片具有独立半透明层次与轻微内高光，默认状态仍保持安静。
- 按钮悬停时高光扩散并轻微浮起，按压时缩放并收缩光晕。
- 动态效果不模糊文字，不影响命中测试，并遵循减少动态效果设置。

## 验证

- 在标题空白、任务文字和空白区域分别执行真实鼠标拖动，确认窗口位置改变。
- 对按钮、输入框和排序柄执行相同操作，确认不会误触窗口移动。
- 在复杂壁纸上捕获静止与拖动完整桌面截图，背景必须具有可辨识的柔化/折射，不得出现黑底、塑料白板或文字模糊。
- 检查失焦、中文输入、清单、勾选、排序、八行滚动及最终打包资源路径。
- 完整运行类型检查、单元测试、端到端测试和安装包构建。
